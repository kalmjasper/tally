What works

  • The fastest way through an import: about one keystroke per transaction.
  • Transfer suggestions get a clear yes or no.
  • The progress ring makes the chore finite.

What doesn't

  • A workflow, not a home screen. Once the inbox is empty there's nothing to look at.

What works

  • Shows what the data model was built for: the net cost per category, with the AMEX bill counted once.
  • "203,40 spent · 117,00 paid back" makes the Tikkie netting visible and easy to trust.
  • The orange "To categorize" cell leads straight to the work.
  • Year mode shows each category over time; the legend turns categories on and off, so you can drop Housing to see the smaller ones.

What doesn't

  • Read-only: you still need A or B to fix anything.
  • "Spent / paid back" per category and "Waiting to be paid back" need small report additions.

API: CategoryTotals(from, to) for this month and last, or for the whole year (it already returns one row per month and category) · parent totals summed in the frontend from ListCategories · a row opens A filtered by category_id and month.

Recommendation

Use all three, each for its own moment.

C for looking, B for working through an import, A for finding and fixing. Together they're the v1.

Screens

  1. Overview (C) is the home page.
  2. Transactions (A) with the inspector. A category in the overview opens it, filtered.
  3. To Categorize: B's one-at-a-time mode over the same list, transfers first. Quick picks start as your recent categories.
  4. Import and Categories as the sheets above.

Build order

  1. Import and the transaction list, so you can see your data.
  2. Inspector: categories, splits, notes.
  3. Linking: transfer suggestions and Link Payments Back.
  4. Overview.
  5. Inbox mode.

Stack

  • Vite, React and TypeScript in web/.
  • buf generate with protoc-gen-es for typed clients; connect-web over gRPC-web with connect-query for caching.
  • TanStack Router keeps the month and filters in the URL, so every view can be bookmarked.
  • Plain CSS with these tokens; Radix only for sheets, popovers and the category picker.
  • Served by tally-server from the same origin; a Vite proxy in development.
